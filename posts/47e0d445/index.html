C语言系统级编程

Week 1

C语言中的对象

一个对象一般有一个对象类型，标记为Type-name。

完全对象类型：大小可知，分配后大小确定。
不完全对象类型：大小未知，分配后大小也确定。

所有对象类型在语义上都是整体的，对象类型在语法上不一定是整体的，如果一个Type-name在语法上整体，标记为T。

对象各个bit组成的二进制串是这个对象的对象表示（Object Representation），对象的值和对象表示可以通过对象类型进行映射。

对象的值一样，对象表示不一定一样：bit包括Value Bits和若干无意义的Padding Bits，由对象类型决定。

sizeof(Type-name)
alignof(Type-name)规定了一个类型的确省对其要求。

类型

Type

  • Arithmetic Type 算数类型
  • Derived Type 派生类型
  • Type-name with Qualifier 限定符修饰类型

对于语法上整体的类型T，typedef T Alias，Alias在语法上是一个整体。

数组派生：typedef typeof(int[5]) AINT; -> int[10][5] <==> AINT[10]

例：int[10][] & int[][10]
int[10][]中的元素类型是int[]不完全累对象类型，不合法。
int[][10]中元素类型T是int[10]。其本身是一个不完全对象类型，不能继续派生数组类型。

指针派生：typedef typeof(int[5]) AINT -> typeof(int[5])* <==> int(*)[5]

例：int(*[10])[5]是一个长度为10的数组，其中每个元素是一个指向长度为5的数组的指针。
其对应的指针类型是int(*(*)[10])[5]

例：int*(**(*)[])[4][5]?

限定符

  • _Atomic
  • const
  • volatile
  • restrict（只能限定对象指针类型，或其构成的多维数组类型）

给定一个类型T，给定一个限定符Q，其限定修饰类型为Q T或T Q，语法上也是整体。

T和Q T(T Q)是两种不同的Type，但大小，表示值，对齐方式一样。

_Atomic限定修饰类型是原子类型，其他三种限定修饰类型统称为限定类型，都有称为原子限定类型。

对于语法上整体呈现的类型T：

  • Q T 等价于 T Q
  • Q T[N]：数组类型，N个Q T；T[N] Q：不合法
  • Q T*：指针类型，referenced type是Q T；T* Q：Q限定T*类型
限定类型形式 派生数组类型（N个元素） 派生指针类型 Q’ 限定修饰类型
QT QT[N] QT* QTQ’ / QQ’T / Q’QT
TQ TQ[N] TQ* TQQ’ / TQ’Q / Q’TQ
T*Q T*Q[N] TQ TQQ’ / TQ’Q

例：const int*(* const*)[4][5]?
例：const int* const?

typeof：

  • const typeof(int*[10]) <==> int* const[10]
  • const typeof(int*[5][10]) <==> int* const[5][10]

_Atomic(T) & _Atomic T:

  • _Atomic(T)是基于T派生的一个原子类型，T不能是数组类型，函数类型，限定类型和原子类型
  • _Atomic T是基于T的原子限定类型，T不能是数组类型，函数类型

lvalue的对象值 & lvalue的右值

lvalue的对象值：lvalue定位对象的对象值

例：int a=0;int b[1]={1}
a的对象值是0，b的对象值是{1}
a的右值是0，b的右值是b第一个元素的地址

5种常量都是非左值：

2.floating-constant（浮点数常量）

4.character-constant（字符常量）

对任何一个标准有符号整数类型T的对象来说，所有bits分成三个部份：1个sign bit，若干个value bits，0到多个padding bits.

假设sign bit加上value bits的个数是N，N是这个对象类型T的宽度(Width)，而N-1是这个类型T的精度(Precision)

T类型对象的对象值范围：−(2N−1)-(2^{N-1})−(2N−1)到2N−1−12^{N-1}-12N−1−1

表达式的递归求值机制

1.表达式可能包含子表达式（递归到初等表达式）
2.表达式的求值蕴含着对其子表达式求值（递归完成）

理解1+2的求值：1:<1,int>，2:<2,int>，1+2:<3,int>；子表达式的求值，是为上一级表达式提供一个值。

什么是Locator Value?

1.Locator Value在标准文本中只出现了一次
2.这是C语言底层核心设计思想体现
3.左值的求值，都必须定位对象，Locator Value就提供了定位对象的手段
4.Locator Value只是一个逻辑概念
5.左值作为子表达式，为上层表达式提供定位自身对应对象的手段

定位非数组对象的lvalue的求值规则

给定一个能定位非数组对象的左值exp，如果这个表达式
1、作为泛型选择的控制表达式（课程后面再介绍）
2、作为sizeof的操作数，例如：sizeof exp
3、作为typeof的操作数，例如：typeof exp，typeof_unqual exp
4、作为alignof的操作数，例如：alignof exp（标准不支持）
-> 不求值
5、作为&的操作数，例如：&exp
6、作为后缀运算符++/–的操作数，例如：exp++
7、作为一元运算符++/–的操作数，例如：++exp
8、作为.的左操作数，例如：exp.
9、作为赋值运算符的左操作数，例如：exp=，exp+=
-> 部分求值

对象标识符的求值示例

int a = 1;，对象六元组：A:0x0061FE10，Obj_T:int，N:a，S:4，Obj_V:1，Align:4

表达式 场景 evaluate结果
a 完整求值 <1, int>（Obj_T的非限定非原子类型）
sizeof(a) 不求值 <4, size_t>
typeof(a) 不求值 等价于int，不是表达式
alignof(a) 不求值 <4, size_t>（标准不支持，部分编译器提供）
&a 部分求值 <0x0061FE10, int*>
++a / --a 部分求值 <2, int> / <0, int>，有副作用
a++ / a-- 部分求值 <1, int>，有副作用
a=2 部分求值 <2, int>，类型匹配不是相同
a+=2 部分求值 <1,int>+<2,int> -> <3, int>，a只求值1次

如何理解a不求值？并不需要真的访问对象a；上层表达式编译时能否推断，不是子表达式lvalue求值的判断标准。

a+=2 vs. a=a+2

a+=2：a只求值1次，部分求值
a=a+2：a求值2次，一次部分求值，一次完整求值

这两个表达式完全不等价；当左操作数exp求值有副作用的时候，exp=exp+n会造成未定义行为（后续介绍）。

从int a观察const int a

与int a的唯一差别是Obj_T:const int，对象六元组其他属性一样；完整求值a;的右值类型是int
a++;、a=2等不合法，a是不可修改左值

定位普通数组对象的lvalue的求值规则

给定一个能定位普通数组对象的lvalue表达式exp，如果这个表达式
1、作为泛型选择的控制表达式
2、作为sizeof的操作数，例如：sizeof exp
3、作为typeof的操作数，例如：typeof exp，typeof_unqual exp
4、作为alignof的操作数，例如：alignof exp（标准不支持）
-> 不求值
5、作为&的操作数，例如：&exp
6、如果exp定位的是一个字符串字面量并用于初始化字符数组
-> 部分求值

思考：exp为什么跟++/–，=的规则没有了？因为数组类型的左值是不可修改左值

数组对象的求值示例

对象 完整求值 不求值 部分求值
int b[1]={1} b: <0x0063FE10, int*> sizeof(b): <4, size_t>；typeof(b)等价于int[1]；alignof(b): <4, size_t> &b: <0x0063FE10, int(*)[1]>
int c[1][1]={1} c: <0x0064FE10, int(*)[1]> sizeof(c): <4, size_t>；typeof(c)等价于int[1][1]；alignof(c): <4, size_t> &c: <0x0064FE10, int(*)[1][1]>

完整求值时，rvalue是对象第一个元素的首地址，rvalue类型是元素对象类型对应的指针类型
b++、b=NULL不行：b的对象值无法修改

可修改左值 vs. 不可修改左值

给定一个左值exp，这个exp定位一个对象的对象类型Type-name：
1、Type-name是数组类型
2、Type-name是const限定类型
3、Type-name是不完全对象类型
4、Type-name是结构体/联合体类型，其成员对象类型有const限定类型
则这个exp被称为不可修改左值，其他exp被称为可修改左值

不可修改左值不能用作前缀/后缀++/–，赋值运算符的操作数
不可修改左值与对象值是不是真的可修改无关，例如：int b[1] = {1};

字符串字面量的求值

1、一个字符串意味着分配（或重用）一个字符数组对象
2、字符串是一个有效的lvalue
3、定位刚刚分配（或重用）的那个字符数组对象

"hello"的对象六元组：A:0x00404000，Obj_T:char[6]，N:N/A，S:6，Obj_V:{'h','e','l','l','o','\0'}，Align:1

表达式 场景 evaluate结果
"hello" 完整求值 <0x00404000, char*>
sizeof("hello") 不求值 <6, size_t>
typeof("hello") 不求值 等价于char[6]，不是表达式
alignof("hello") 不求值 <1, size_t>
&"hello" 部分求值 <0x00404000, char(*)[6]>
char str[]="hello" 部分求值 初始化字符数组，不对"hello"求值

思考题：char* p="hello"和char str[]="hello"这两个hello哪一个需要evaluate？
第一个需要evaluate，表达式的rvalue赋值给对象p；第二个用于初始化字符数组str，不进行evaluate

"hello"分配的对象size为什么一定是6？因为这个对象的对象类型是char[6]
char str[8]="hello"：第6个’\0’是"hello"自身带的，后面2个’\0’是自动填充的

复合字面量的求值

1、Compound Literal意味着分配一个指定类型的对象
2、Compound Literal是一个有效的lvalue表达式
3、定位刚刚分配的那个对象

(int){1}的对象六元组：A:0x0066FE10，Obj_T:int，N:N/A，S:4，Obj_V:1，Align:4

表达式 场景 evaluate结果
(int){1} 完整求值 <1, int>
sizeof((int){1}) 不求值 <4, size_t>
typeof((int){1}) 不求值 等价于int，不是表达式
alignof((int){1}) 不求值 <4, size_t>
&(int){1} 部分求值 <0x0066FE10, int*>
++(int){1} / (int){1}++ 部分求值 <2, int> / <1, int>，有副作用
--(int){1} / (int){1}-- 部分求值 <0, int> / <1, int>，有副作用
(int){1}=2 部分求值 <2, int>

(const int){1}是不可修改左值；(int[1]){1}完整求值是<0x0067FE10, int*>，&(int[1]){1}是<0x0067FE10, int(*)[1]>

(int){1}+=2 vs. (int){1}=(int){1}+2：前者分配一个对象，后者分配两个对象

理解sizeof和&

给定一个定位非变长数组对象的lvalue表达式
1、作为sizeof操作数，该lvalue不求值
2、sizeof(lvalue)的语义是获得lvalue定位对象的大小
3、这个对象的大小由对象类型可知，编译时可以推断出来
4、对象的size在生命周期内不会变化

给定一个定位对象的lvalue表达式
1、跟&结合，lvalue做部分求值
2、如果lvalue定位对象的Storage Duration是static，其对象地址编译时可知
3、否则该对象地址运行时才可获得

定位指针类型对象的lvalue的求值

int a=1; int* p=&a;，p定位一个对象，其对象类型为int*
&a部分求值得到<0x0061FE10, int*>，赋值后p的对象值变成0x0061FE10

p的对象六元组：A:0x0068FE10，Obj_T:int*，N:p，S:4，Obj_V:0x0061FE10，Align:4
p; -> <0x0061FE10, int*>；sizeof(p)/typeof(p)不求值；&p -> <0x0068FE10, int**>；p++/--、p=NULL部分求值

*exp形式的lvalue

设一个表达式exp的evaluate之后的值为<rvalue, rvalue_Type>
如果rvalue_Type是一个完全对象的指针类型，则*exp可以定位一个对象M
1）对象M的Address为Value
2）对象M的Object Type为Value_Type对应的Referenced Type
3）对象M其他属性随之确定

*exp是一个lvalue，定位一个对象，仅此而已，不是获得*exp这个表达式的值；表达式的值只有在evaluate之后才有
Referenced Type和Pointer Type的对应关系是指针关系的核心概念

例：int a=1; int* p=&a;
p是*的操作数，做完整求值，即<0x0061FE10, int*>
*p定位对象M：地址0x0061FE10，对象类型是int*的Referenced Type即int，其他属性依次确定
&(*p)是<0x0061FE10, int*>，*p是<1, int>，sizeof(*p)是<4, size_t>

给定两个左值E1和E2，假设定位到的对象分别是O1和O2，如果O1和O2的地址相同，且对象类型也一样，则 (E1)≡(E2)(E1)\equiv(E2)(E1)≡(E2)

思考：为什么C语言标准里面不使用变量这个概念？a和*p在行为上是完全一致的，a如果是变量，p为什么不是？
int a=1; const int* p=&a;：a和p定位的是同一块内存吗？是同一个对象吗？
const int a=1; int* p=&a;：*p=2能否编译通过？会引起什么问题？未定义行为

指针算术：p+n

1、p完整求值，得到<rvalue, rvalue_type>
2、计算sizeof(*p)
3、p+n的value = p的rvalue + sizeof(*p)*n
4、p+n的rvalue_Type不变

例：int a=10; int* p=&a;，p是<0x0061FE10, int*>，p+n是<0x0061FE10+4*n, int*>

p+1是合法表达式；*(p+1)导致未定义行为；*(p+2)也导致未定义行为；p+2呢？
重要概念：One Past The Last Element of The Array Object，后续详细介绍
